# 人工智能产业政策工作流说明

本工作流用于从“人工智能相关政策候选”中识别人工智能产业政策，对确认样本进行政策工具分类，并分别生成中央、省级和地级市月度面板。

仓库仅提供代码和方法说明，不提供候选政策、原始法规、模型输出或面板数据。

## 产业政策识别口径

产业政策采用窄口径定义。文件需要同时满足：

1. 政策主体是政府或政府部门；
2. 文本包含具体政策措施，或正式、明确、直接针对人工智能产业的导向性安排；
3. 文本直接偏向人工智能产业、直接产业链或人工智能专属经济活动；
4. 政策目标影响长期经济结构或资源配置。

直接目标包括人工智能产业、模型研发与应用、基础模型和生成式人工智能、算法、智能算力、人工智能芯片、训练与推理、数据标注和语料、平台服务、具身智能及相关产业生态。

一般数字经济、普通信息化、智慧城市、普通数据治理、软件服务、互联网平台、网络安全、电子政务、智能制造、机器人或自动化政策，只有在人工智能或直接产业链被明确列为目标时才纳入。

## 主要脚本

| 脚本 | 用途 |
|---|---|
| `scripts/ai_policy_pipeline.py` | 人工智能产业政策识别主入口 |
| `scripts/build_ai_fulltext_candidates.py` | 为候选补充全文和证据包 |
| `scripts/select_ai_boundary_candidates.py` | 抽取第一阶段边界样本 |
| `scripts/merge_ai_dual_vote_boundary.py` | 合并第一票和第二票 |
| `scripts/build_ai_dual_vote_final_full.py` | 将复核结果拼回全候选集 |
| `scripts/ai_policy_tool_refiner.py` | 对确认样本进行政策工具细分类 |

对应入口位于 `runbooks/`。运行前应通过环境变量或脚本参数设置候选和输出目录，不要把真实路径或认证信息写进代码。

## 两阶段判断

第一阶段使用单模型处理全部候选，输出产业政策判断、置信度、证据和解析状态。第二阶段只处理置信度边界、失败和预先定义的边缘类型，保留两票结果及最终规则。

这套设计兼顾速度和可审计性。边界区间应在小样本验证后固定，并随研究报告一并说明。

## 政策工具与面板

对最终确认为产业政策的文件进行多标签工具分类，包括事前或事后、供给端或需求端、支持或限制、具体措施或导向性安排，以及工具强度、目标、覆盖范围和证据文本。

面板按中央、省级、地级市分别生成，不把中央政策机械复制到每个城市。所有聚合结果都应能够回溯到文档级分类记录。
